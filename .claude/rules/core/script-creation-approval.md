# 스크립트 생성 사전 승인 (Mandatory)

> 모든 볼트에 동일 적용. 모든 에이전트 공통.

## 규칙

**남는 것과 안 남는 것을 가른다** (2026-09-08 개정). 종전에는 모든 `.ps1`/`.py` 생성에
사전 승인을 요구했는데, 이미 맡긴 구현에 필요한 보조 파일까지 매번 끊겨 개발이 안 됐다.

| 무엇 | 승인 |
|------|------|
| **저장소에 남는 스크립트** — 재사용·자동화·도구 | **사전 승인 필수** (아래 보고 항목) |
| **자동화 등록** — 스케줄러·훅·데몬·CI | **사전 승인 필수.** 사람이 안 볼 때 스스로 도는 것이라 등급이 다르다 |
| 이미 맡긴 작업의 일회성 보조 — `$env:TEMP` 에 쓰고 그 자리에서 지우는 것 | 불필요. 단 **작업 보고에 무엇을 만들어 어떻게 지웠는지 적는다** |
| 기존 스크립트 수정 | 그 수정이 맡긴 작업 범위면 불필요. 범위 밖이면 보고 |

- 승인 대상은 **생성 전에** 보고한다. 만들고 나서 통보하지 않는다.
- 일회성 보조도 **볼트 안에 남기지 않는다** (`temp-file-management.md`).

## 보고 항목

1. 스크립트의 목적 (왜 필요한가)
2. 생성 경로
3. 실행 시 영향 범위 (어떤 파일/폴더에 영향을 주는가)
4. 일회성인지 영구 보관인지

## 금지 사항

- 사용자 모르게 **자동화를 등록**하는 행위 금지 (스케줄러·훅·데몬·CI). 사람이 안 볼 때
  스스로 도는 것은 언제나 사전 승인이다.
- **맡긴 작업 범위 밖**의 기존 스크립트를 무단 수정하는 행위 금지.
- 저장소에 남는 스크립트를 보고 없이 만들고 "만들어서 실행했습니다" 로 사후 통보하는 행위 금지.
